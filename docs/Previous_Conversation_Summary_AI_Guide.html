Previous Conversation Summary AI

One card on the Opportunity that lists everything already said to a client (emails, tasks, meetings, notes, case comments and calls) and, at the press of a button, writes an AI Summary of it: overall summary, sentiment, key insights, concerns, next actions and the next meeting.

How it works

  1. 1Open the caseA case manager opens an Opportunity with the card on it.No AI cost
  2. 2History gatheredEmails, tasks, events, notes, case comments and Convoso calls, as the user (user mode).SOQL + 1 Data 360 query
  3. 3Press GenerateNothing runs on load or on the timer. Only the button calls the AI.Button only
  4. 4Text cleanedEvery line goes through neutralise(). At most 60 entries and 12,000 characters.Injection guard
  5. 5Model callaiplatform.ModelsAPI, model sfdc_ai__DefaultGPT4Omni, inside the org.1 billed call
  6. 6Card shownThe JSON reply is parsed into the boxes. A non-JSON reply still shows as text.Never blank

What the card shows

Built from the AIsummarycon template (static resource on SIT). Same order, top to bottom.

HeaderClient initials, case name in large type, View record.
AI SummaryGenerate AI Summary button, Last updated time, AI-generated badge.
Overall SummaryTwo to four sentences: where things stand and what to do next.
Customer SentimentPositive, Neutral, Negative or Unknown, with one line why.
Calls · Emails · NotesCounted from the real history, not by the AI.
Next Key MeetingFrom the summary, when the history names one.
Key InsightsUp to 5.
Customer ConcernsUp to 5.
Recommended Next ActionsUp to 5, priority + due date.
Ask about this caseType a question; plain-text answer from the same history.
Recent CommunicationsIcon per type, date and time, type tag, title, 2-line preview, search, type filter, View source (opens the record; a call opens its recording).
Calls have no transcriptConvoso stores when a call happened, who took it and how long it ran. The AI is told never to invent what was said on a call.
Differences from the imageRows show their own text, not an AI one-liner and tags (that would bill a call per row). Next actions have no tick boxes because nothing would save them.

Production deploy (Naga)

  1. Confirm Einstein is on in Prod. It is today (checked 23 Oct). Case Manager AI already uses the same Models API there.
  2. Deploy only these three components. Never deploy the whole classes folder from this repo: it is older than the orgs.
    Command
    sf project deploy start -o prod -m ApexClass:PreviousConversationsAgent -m ApexClass:PreviousConversationsAgentTest -m LightningComponentBundle:previousConversationsAI -l RunSpecifiedTests -t PreviousConversationsAgentTest -t PreviousConversationsServiceTest
  3. Ask case managers to refresh their browser. Open tabs keep the old card.
  4. Check it. Open an Opportunity with history, press Generate AI Summary, and check the boxes fill in. Ask one question in the ask box.

Decisions

DateDecisionWhy
4 SepThe AI never runs on load or on the timer; only the history refreshes.Every AI call is billed; a timer would bill with nobody reading.
4 SepSend the transcript built as the user, never a record Id.The AI only sees what the case manager can already see.
23 OctNo external client app or Agent API: call the Models API inside Salesforce.Naga: "I am using this AI inside the Salesforce." Same pattern as Case Manager AI, already live.
23 OctCard design = the AIsummarycon template.Naga uploaded it as the design to follow, history included.
